1Asymptotic notations: O, Ω, Θ  ★★★

In one minute
What it solves

Describes how fast an algorithm's running time grows as the input gets large, ignoring constants.

The concept

O gives an upper bound, Ω a lower bound, Θ a tight bound (both). To prove f(n) = Θ(g(n)), find constants c1, c2, n0 that sandwich f.

Where it is used

Comparing algorithms before writing code; predicting whether a program will scale.

Definitions
f = O(g): f(n) ≤ c·g(n);   f = Ω(g): f(n) ≥ c·g(n);   Θ = both, for all n ≥ n0
Growth order
1 < log n < √n < n < n log n < n2 < n3 < 2n < n!
From slowest-growing to fastest.
Worked example — prove 3n² + 5n + 2 = Θ(n²)
Find c1, c2 and n0.
  1. Lower bound3n² + 5n + 2 ≥ 3n² for n ≥ 1 → c1 = 3
  2. Upper bound5n ≤ 5n² and 2 ≤ 2n² for n ≥ 1, so the sum ≤ 10n² → c2 = 10
  3. Conclude3n² ≤ f(n) ≤ 10n² for all n ≥ n0 = 1
f(n) = Θ(n²) with c1 = 3, c2 = 10, n0 = 1.
Practice
  1. Order: slowest to fastest growth.n log n, n², 2n, log n.
    log n < n log n < n² < 2n.
  2. Answer: true or false? Give the reason.2n+1 = O(2n).
    True: 2n+1 = 2 × 2n, so c = 2 works.

2Recurrence relations: iteration and the characteristic equation  ★★★

In one minute
What it solves

Turns “the cost of n in terms of smaller n” into a closed formula or a growth rate.

The concept

Iteration: expand T(n) repeatedly and spot the pattern. Linear recurrences with constant coefficients: solve the characteristic equation; distinct roots r1, r2 give an = A r1n + B r2n.

Where it is used

Analysing recursive algorithms; counting problems (Fibonacci-type).

Common patterns
T(n) = T(n−1) + n ⇒ Θ(n2);   T(n) = T(n/2) + 1 ⇒ Θ(log n);   T(n) = 2T(n/2) + n ⇒ Θ(n log n)
Worth remembering.
Characteristic equation
an = c1an−1 + c2an−2 → r2 − c1r − c2 = 0 → an = A r1n + B r2n
Use the initial values to find A and B.
Worked example — a linear recurrence
an = 5an−1 − 6an−2, a0 = 2, a1 = 5.
  1. Characteristic equationr² − 5r + 6 = 0 → (r − 2)(r − 3) = 0 → r = 2, 3
  2. General solutionan = A·2n + B·3n
  3. Use a0 and a1A + B = 2;  2A + 3B = 5 → B = 1, A = 1
  4. Check a2formula 4 + 9 = 13; recurrence 5·5 − 6·2 = 13 ✓
an = 2n + 3n.
Practice
  1. Find: the growth rate.T(n) = T(n/2) + 1 (binary search).
    Halving until 1 takes log2 n steps: Θ(log n).
  2. Find: the closed form.an = 3an−1, a0 = 2.
    an = 2 · 3n.

3The Master theorem  ★★★

In one minute
What it solves

Gives the growth rate of divide-and-conquer recurrences T(n) = aT(n/b) + f(n) in one step.

The concept

Compare f(n) with nlogba (the work done by the leaves). Whichever is bigger wins; if they are equal, multiply by log n.

Where it is used

Merge sort, binary search, Karatsuba, Strassen and any recursive split.

Form
T(n) = aT(n/b) + f(n),   a ≥ 1, b > 1;   let p = logb a
The three cases
Case 1: f = O(np−ε) ⇒ Θ(np);   Case 2: f = Θ(np) ⇒ Θ(np log n);   Case 3: f = Ω(np+ε) and a f(n/b) ≤ c f(n) ⇒ Θ(f(n))
How to solve it in the exam
  1. Read off a, b and f(n).
  2. Compute p = logb a.
  3. Compare f(n) with np and pick the case.
  4. For case 3, check the regularity condition.
Worked example — three recurrences
(i) T(n) = 9T(n/3) + n   (ii) T(n) = 2T(n/2) + n   (iii) T(n) = 3T(n/4) + n²
  1. (i)p = log3 9 = 2; f = n is smaller → Case 1 → Θ(n²)
  2. (ii)p = log2 2 = 1; f = n equal → Case 2 → Θ(n log n) (merge sort)
  3. (iii)p = log4 3 ≈ 0.79; f = n² bigger → Case 3; check 3(n/4)² = (3/16)n² ≤ c n² ✓ → Θ(n²)
Θ(n²), Θ(n log n), Θ(n²).
Common trap
It does not apply to every recurrence: T(n) = T(n − 1) + n has no n/b form, and 2T(n/2) + n/log n falls between the cases.
Practice
  1. Find: the growth rate.T(n) = 4T(n/2) + n.
    p = log2 4 = 2 > 1 → Case 1 → Θ(n²).
  2. Find: the growth rate.T(n) = T(2n/3) + 1.
    a = 1, b = 3/2, p = 0, f = 1 = n0 → Case 2 → Θ(log n).

4P, NP, NP-complete and NP-hard  ★★

In one minute
What it solves

Classifies problems by whether they can be solved, or only checked, in polynomial time.

The concept

P: solvable in polynomial time. NP: a proposed answer can be checked in polynomial time. NP-complete: in NP, and every NP problem reduces to it. NP-hard: at least as hard as NP-complete (may not be in NP).

Where it is used

Knowing when to stop looking for a fast exact algorithm and use approximation or heuristics instead.

Relationships
P ⊆ NP;   NP-complete = NP ∩ NP-hard;   if any NP-complete problem is in P, then P = NP
To show X is NP-complete: show X ∈ NP, then reduce a known NP-complete problem to X.
Worked example — classify four problems
Sorting, checking a Sudoku solution, 3-SAT, the halting problem.
  1. Sortingsolvable in O(n log n) → P
  2. Checking a filled Sudokuverify rows, columns, boxes quickly → in NP (and in P)
  3. 3-SATCook–Levin: NP-complete
  4. Halting problemnot even decidable → NP-hard, not in NP
P; NP; NP-complete; NP-hard.
Common trap
The reduction goes from the known NP-complete problem to the new one, not the other way round.
Practice
  1. Answer: what follows?Someone finds a polynomial-time algorithm for an NP-complete problem.
    Then P = NP.
  2. Answer: which class?Problems whose proposed solutions can be checked in polynomial time.
    NP.

5The satisfiability problem (SAT)  ★★★

In one minute
What it solves

Decides whether a logic formula can be made true by some assignment of true/false values.

The concept

Write the formula in CNF (an AND of clauses, each an OR of literals). 2-SAT (two literals per clause) is in P; 3-SAT is NP-complete. DPLL solvers use unit propagation and backtracking.

Where it is used

Hardware and software verification, scheduling, planning, puzzle solving.

Definitions
CNF = ∧ of clauses; clause = ∨ of literals; satisfied ⇔ every clause has at least one true literal
n variables give 2n possible assignments to try by brute force.
Worked example — find a satisfying assignment
φ = (x ∨ y) ∧ (¬x ∨ z) ∧ (¬y ∨ ¬z).
  1. Try x = Tclause 1 is true; clause 2 forces z = T
  2. z = Tclause 3 needs ¬y, so y = F
  3. Check(T ∨ F) = T, (F ∨ T) = T, (T ∨ F) = T ✓
Satisfiable: x = T, y = F, z = T.
Practice
  1. Answer: satisfiable? Give the reason.(x) ∧ (¬x).
    No: x cannot be both true and false.
  2. Answer: which is in P?2-SAT or 3-SAT?
    2-SAT is in P; 3-SAT is NP-complete.

6Searching and sorting: costs and the n log n lower bound  ★★★

In one minute
What it solves

Picks the right search or sort for the situation and predicts how many comparisons it needs.

The concept

Linear search checks every item (O(n)); binary search halves a sorted list (O(log n)). Comparison sorts cannot beat Ω(n log n); counting and radix sort avoid comparisons.

Where it is used

Every database, search engine and spreadsheet.

Bounds
binary search worst case = ⌈log2(n + 1)⌉ comparisons;   comparison sort ≥ log2(n!) ≈ n log2 n
Worked example — comparison counts and a sort table
A sorted list of 1000 items. Compare the common sorts.
  1. Linear search, worst1000 comparisons
  2. Binary search, worst⌈log2 1001⌉ = 10
  3. Bubble / insertion sortO(n²) worst; insertion is O(n) on nearly sorted data
  4. Merge sortO(n log n) always, needs extra memory
  5. Quick sortO(n log n) on average, O(n²) worst (bad pivots)
Binary search needs at most 10 comparisons on 1000 sorted items, against 1000 for linear search.
Common trap
Binary search only works on sorted data.
Practice
  1. Find: the worst case.Binary search on 1 000 000 sorted items.
    ⌈log2 1 000 001⌉ = 20 comparisons.
  2. Answer: which sort?Which sort guarantees O(n log n) even in the worst case: quick sort or merge sort?
    Merge sort.
